# 远程合作

远程合作使用 [Terracotta 0.4.2](https://github.com/burningtnt/Terracotta/tree/v0.4.2) 和 EasyTier，把现有 2–4 人合作房间连接到异地好友。游戏仍由房主运行，不需要自行租用云服务器。双方必须使用相同版本的游戏。

## 玩家操作

1. 主菜单选择「远程合作 · Terracotta」。房主填写称呼、房间名称、人数与难度，创建房间，或恢复独立的合作存档。
2. 等待界面显示远程通道已连接，再复制 `U/XXXX-XXXX-XXXX-XXXX` 格式的邀请码给好友。邀请码相当于房间密钥，仅交给可信的人。
3. 好友打开相同入口，粘贴邀请码，点击加入。各自选择天赋、准备，房主开始游戏。
4. 断线后点击「重连上次房间」。游戏会重新建立远程通道，再用原成员凭据恢复角色，不复用可能已经失效的本地转发端口。房主重启或恢复存档后会生成新邀请码；原成员粘贴新邀请码加入时仍带上自己的重连凭据。
5. 离开房间、返回主菜单和正常退出游戏会关闭本游戏的远程房间。桌面 Terracotta 程序可能保留为空闲实例，以便再次使用，不强制终止其他应用共享的程序。

与局域网合作共享全部既有规则：独立 SAN、背包和天赋，共享世界与剧情，房主保存，原成员重连，死亡后观战，全队暂停，六条公开结局。详细规则见[局域网合作](局域网合作.md)。隐藏路线、特殊空间、DLC、手机小游戏与相册的联机支持范围没有扩大。

## 平台与连接限制

- Windows x86_64、Linux x86_64 包内附带经过校验的 Terracotta 执行文件，须完整解压并保留 `terracotta/` 目录。首次运行允许游戏与 Terracotta 通过系统防火墙。
- Android ARM64 使用随 APK 打包的官方原生库、Godot 插件和 VPN 服务。首次连接需要在系统弹窗允许 VPN；拒绝后可继续单人或局域网模式。VPN 仅允许本游戏使用，只安装 Terracotta 的虚拟网络路由，不接管设备全部流量。服务通知提供返回游戏入口，离开房间后停止服务。
- Android 系统一次通常只允许一个 VPN。正在使用其他 VPN／虚拟组网工具时，需要由玩家决定是否切换。房主应保持游戏在前台；锁屏、杀后台、切换网络后可能掉线，可回到游戏重连。
- Terracotta 使用公共节点帮助发现与打洞，不能保证所有校园网、企业网、移动网络或运营商组合都能连接。120 秒未完成连接会提示失败，可取消、切换网络再试；没有自动回退到收费中继，也没有自建中继服务器。
- 已有 Terracotta 正在服务另一个房间时，游戏提示先结束该房间，不覆盖它。发现其他 Minecraft 房间导致扫描到错误端口时，也不会发放本游戏的可用邀请。
- Android 0.4.2 JNI 接口没有公开动态 Scaffolding 端口，接入层验证其默认 `13448` 端口。该端口冲突时安全失败，需关闭占用程序并重启游戏；不会盲目宣布建房成功。

## 开发与构建

开发环境先按当前平台获取依赖：

```bash
python tools/terracotta.py --platform linux
# Windows 开发环境改为 --platform windows
godot --editor --path .
```

下载仅发生在开发／打包阶段，游戏运行时不会下载或执行未知文件。`tools/terracotta.py` 固定版本与各平台 SHA256，校验失败终止构建。Linux、Windows 的导出脚本把执行文件与许可放入包内；Android 导出先安装官方 Gradle 模板，再注入 `platform/android/terracotta/` 中的 Java 源码和原生库，继续验证 Vulkan、启动横屏／全屏、签名和全部 ELF 的 16 KB 页对齐。

| 层 | 职责 |
| --- | --- |
| `TerracottaProtocol` | 邀请码校验、生成、严格的回环端点解析 |
| `TerracottaBridge` | 本地发现公告、TCP 探活、Scaffolding 游戏端口核验 |
| `TerracottaGateway` | 桌面回环 HTTP／Android JNI 适配，异步且限制响应大小 |
| `TerracottaSession` | 连接状态机、超时、取消、房间归属和清理 |
| `LanFlow` / `LanPanel` | 远程入口、邀请码、重连凭据、既有大厅和游戏展示 |
| `LanSession` / `LanTransport` | 原有房主权威游戏逻辑与 ENet；无需更换玩法或同步协议 |

Terracotta 原本通过 Minecraft 局域网公告发现服务器，因此适配层在 ENet UDP 端口的同号 TCP 端口提供最小探活响应，并向本地 `4445` 发送公告。实际游戏流量仍是 ENet UDP。建房后查询 Scaffolding `c:server_port`，确认转发的是本游戏端口；加入时只接受 `127.0.0.1` 与合法端口。

ENet 协议升级为版本 2，两端启用 range coder 压缩。真实集成中未压缩的大型快照分片会在隧道中停滞，而小型大厅消息可以到达；启用数据报压缩后验证完整快照与重连。旧合作客户端不能混用，双方均需更新。

桌面 HTTP API 仅访问回环地址，不启用重定向。取消时不直接丢弃尚未完成的建房请求，而是等待响应、核对房间后清理，防止迟到请求留下房间。Android 的可能阻塞的 JNI 调用在单独工作线程执行，VPN 文件描述符由服务持有，连接关闭后释放。

许可证、上游固定源码版本及未修改的 API 源码说明见 [Terracotta 声明](../third_party/terracotta/NOTICE.md)。上游运行日志可能包含邀请码，分享前应删去邀请码和网络信息。

## 验证方式与边界

```bash
python tools/test_remote.py --unit
python tools/test_remote.py --players 4
python tools/test_lan.py --rules
python tools/test_lan.py --players 2 --ui
```

单元测试覆盖邀请码、转发端点、重复状态、取消过程中迟到的请求，以及其他应用已有房间的保护。集成测试运行2–4 个真实 Godot 进程、同数量官方 Terracotta 实例与一个本地 EasyTier 发现节点，验证 ENet 游戏数据、整条通道重建、原角色恢复及退出。测试专用配置关闭物理网卡绑定，使本地发现节点可通过回环访问；正式运行不修改这个上游设置。

GitHub Actions 的联机任务执行协议和真实通道测试、既有 ENet 回归及 X11／Wayland／Vulkan Mobile 界面检查；Android 任务构建含插件的 APK。日志报告不上传测试邀请码和上游私有日志。

本地通道测试不能替代跨运营商 NAT 穿透、Android 系统 VPN 授权／撤销、Windows 防火墙提示及真实手机混合联机验收。这些设备和网络场景必须单独记录，不能用构建成功宣称已经完成真机测试。
