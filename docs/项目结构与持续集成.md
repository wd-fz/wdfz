# 项目结构与持续集成

根目录的 `project.godot` 仍是 Godot 项目入口，F5 运行 `game/app/app.tscn`。这次整理基于正式校园已合并的 main，保留世界 ID、模块 ID、存档格式、模型与音频资源路径。

## 目录与归属

```text
project.godot                 编辑器项目与输入映射
export_presets.cfg            Linux / Windows x86_64 与 Android ARM64 调试／正式包
.godot-version                本地与 CI 共用的引擎版本

game/
  app/                       主场景、GameApp、SessionFactory
  core/                      会话、模块协议、通用数据校验
  features/<功能>/           玩法规则与纯数据算法
  infrastructure/
    content/                 CampusData：读取受信任布局并缓存
    persistence/             SaveStore、RunRecords：存档与记录文件
    settings/                GameSettings：本机设置
    diagnostics/             Playtest：试玩记录
  presentation/
    actors/                  角色、交互、第一人称手部；玩家场景就近存放
    world/                   场景路由、校园几何、灯光与世界表现
    ui/                      菜单、HUD、触屏、手机与记录面板
    audio/                   声音与字幕表现
    cinematics/              开场、死亡、结局演出
    phone/                   相机照片合成

content/                     可编辑的 WorldDefinition、Theme 配置
assets/                      运行时模型、贴图、音频与布局数据

tests/
  run_tests.gd               显式执行顺序和统一结果
  support/                  断言转发、场景树与输入测试辅助
  suites/                   按功能分组的 Godot 测试套件
  tooling/                  Python 检查工具自身的回归

tools/
  check.py                   统一检查入口
  export.py                  导出、打包与包内资源验证
  export_android.py          Android Debug APK、签名与包内容验证
  ci/                        引擎安装、结构检查、日志与导出验证器
  capture/                   所有 Godot 截图脚本
  export_scenes/             旧 Web 建筑导出与 WorldDefinition 生成
  audio_bake/                旧 Web 音效烘焙

docs/                        架构、接入和验证记录
  plan/                     标题命名的计划；状态统一在 README.md
pictures/                    人工检查截图；不作为游戏纹理导入
.github/                     CI 与共用引擎安装 action
build/                       日志、导出包与临时截图；不提交
```

场景和直接附着的脚本放在一起。`assets/` 与 `content/` 保持原路径，避免为目录整理重写几千项模型／纹理导入关系。脚本移动时保留 `.gd.uid`；资源注册和生成工具同步到新路径。

`SessionFactory.create()` 是新增模块的注册入口，显式按顺序构造模块、注入内容数据。`GameApp` 负责应用接线；它仍承接较多跨系统协调，本次没有宣称完成所有业务控制器的拆分。后续拆分应按完整命令流程进行，并保留已有回归。

规则只能依赖 `game/core/` 与 `game/features/`；核心层不能反向依赖具体玩法。文件、设备、场景树和资源加载留给外层。结构检查扫描所有规则脚本，包括不继承 `FeatureModule` 的辅助算法，并检查已登记类型的跨层引用。它是静态保护，不能替代 Godot 编译和运行验证。`DreadModule` 的室外比例已改为由组合层注入，不再自行读取校园文件。

## 本地命令

需要 Python 3.10+、`.godot-version` 指定的 Godot 标准版。无需安装 Python 第三方库；旧资源导出工具的额外依赖按各自说明安装。

```bash
python tools/check.py --static-only       # 目录、UID、资源路径、依赖边界、工具测试
python tools/check.py                     # 上述检查 + 导入 + 无窗口回归
python tools/check.py --mode windowed     # Vulkan Forward+ 有窗口全量回归
python tools/check.py --mode windowed --renderer mobile  # Vulkan Mobile 全量回归
python tools/check.py --windowed          # 顺序执行两种回归
```

有窗口测试需要显示服务，Linux CI 用 Xvfb 与 Mesa Lavapipe 软件 Vulkan，显式选择 ICD；不再使用 OpenGL。移动端比例和合成触摸测试不能代替 Android 真机验收。首次导入五档校园资源可能需要几分钟；导入与无窗口回归各有 15 分钟上限，窗口回归上限为 60 分钟。

检查日志与 `summary.json` 在 `build/reports/<模式>/`（窗口模式另带 `-forward_plus` 或 `-mobile` 后缀）。非零退出、引擎打印错误、超时、回归没有给出完整且非空的成功汇总都会失败；脚本编译错误导致引擎不退出时会主动终止该进程。日志在失败后也保留。氛围规则测试使用固定种子并在结束后还原，避免受之前创建的随机游戏局影响。有窗口路线测试通过真实按键跳过演出后检查结局卡，同时验证菜单／新局取消开场和结局演出时不执行旧回调；速通开场通过 Escape 跳过后验证计时和控制权恢复。日志列出当前用例，便于定位长测试。

新增 Godot 脚本后先在编辑器导入，提交生成的 `.gd.uid`；CI 不替开发者补交 UID。测试仍使用隔离的 `user://framework-tests/`，截图脚本使用自己的测试目录。

## GitHub Actions

[Godot CI](../.github/workflows/godot.yml) 在 PR、main 推送及手动运行时触发，不按文件路径跳过整条检查。同一分支的新运行取消旧运行。权限为 `contents: read`，不发布 Release，也不自动合并 PR。

| 检查 | 内容 | 产物 |
| --- | --- | --- |
| Structure and tooling | 结构、UID、资源路径、规则依赖、Python 工具回归 | `reports-structure` |
| Regression (headless) | 独立导入与全量无窗口回归；不验证 GPU | `reports-headless-forward_plus` |
| Regression (windowed) | Xvfb + Lavapipe，桌面路径的全量窗口回归 | `reports-windowed-forward_plus` |
| Regression (Vulkan Mobile) | Xvfb + Lavapipe，移动渲染路径的全量窗口回归 | `reports-windowed-mobile` |
| Desktop builds | 三组回归成功后，导出 Linux／Windows，以 Vulkan 验证 Linux 启动与 PCK 内容 | `desktop-builds-<提交 SHA>`、`reports-export` |

三组回归使用矩阵并行，某一模式失败不会取消其他模式。窗口检查必须取得 Vulkan RenderingDevice 并通过真实像素检查，自动回退不能冒充通过。下游构建只在前置检查通过后开始；前置失败时构建显示跳过属于依赖关系，不表示通过。没有专用凭据或外部服务要求。测试或导出失败仍上传已有日志，保留 14 天；较大的桌面包保留 3 天。

引擎及导出模板从 Godot 官方发布下载，核对官方 SHA512。版本仅由 `.godot-version` 控制；共用 action 缓存安装好的版本。首次模板下载约 1.26 GB，缓存只保留各 job 所需的桌面模板或 Android Gradle 模板，不保存整份下载压缩包。不缓存项目 `.godot/`，保证 CI 能发现缺少资源或 UID 的问题。

若配置 main 分支保护，选择上表五个实际检查名称；仓库管理员的分支保护设置不属于 workflow YAML 内容。

## 导出与下载

Linux 上可安装与 CI 相同的官方引擎及两个桌面模板：

```bash
python tools/ci/install_godot.py --templates
# 将命令打印的引擎路径设为 GODOT_BIN，或把其 bin 目录加入 PATH。
python tools/export.py  # 需可用的 Vulkan 显示服务；CI 用 xvfb-run -a
python tools/export.py --platform linux
```

其他系统可从 Godot 编辑器安装同版本模板，使用 `export_presets.cfg` 导出；上述安装脚本面向 Linux x86_64。

到 GitHub 的 **Actions → Godot CI → 成功的运行 → Artifacts** 下载 `desktop-builds-<SHA>`。里面是分别打包的 Linux 和 Windows ZIP，完整解压后运行；可执行文件和 `.pck` 放在同一目录。每包带许可证、启动说明、来源提交与引擎版本，摘要日志记录包的 SHA256。

导出包含动态加载的五档模型、音频、布局 JSON；排除测试、工具、文档与检查截图。Linux 原生 release 可执行文件在 Vulkan 窗口中通过 `-- --startup-smoke` 执行短启动与正常关闭检查：菜单实际播放背景音，再发出窗口关闭请求，等待混音回收后退出；要求完成标记且脚本／资源错误仍判失败。另用同版本编辑器加载**导出后的 PCK**，验证新局、校园／实验楼／教室、42 个室内布局、五档模型和声音索引，并验证开发目录未进入包。验证器从仓库外部传给引擎，不随游戏发布。Linux 验证还要求真实 Vulkan 设备、Forward+ 和校园帧回读；构建元数据记录后端与验证范围。Windows 目前只验证交叉导出成功，没有宣称完成 Windows 真机运行。

这些包用于开发验证。正式发布仍需设备、性能、字体分发及完整游玩验收；Linux 使用系统中文字体（如 Noto Sans CJK）。

## Android 调试包

[Android Debug workflow](../.github/workflows/android-debug.yml) 在 main 推送和手动运行时独立构建 APK，不等待桌面测试矩阵。使用固定版本 Godot 的官方 `android_source.zip` Gradle 模板及其中的预编译引擎库，校验下载 SHA512；不编译引擎，不依赖 NDK。CI 使用 JDK 17、Android SDK platform-tools、build-tools 36.0.0 与 platforms;android-36；Gradle wrapper 由官方模板提供。

预设名为 `Android Debug`：ARM64（`arm64-v8a`）、最低 API 24／Android 7.0、目标 API 36，包名 `org.wdfz.godot.debug`，横屏与 Vulkan Mobile 渲染；设备必须提供 Vulkan，禁用 OpenGL 回退。项目启用 ETC2／ASTC 纹理导入，包内保留原有五档资源。构建脚本使用隔离的 Godot 编辑器配置，调试签名保存在用户目录 `~/.android/wdfz-debug.keystore`，不会修改个人编辑器中的 Android SDK 与签名设置。

Linux 本地构建需要 Python 3.10+、JDK 17 或以上，以及上述 Android SDK 工具：

```bash
python tools/ci/install_godot.py --android-debug
# 将安装器输出的引擎目录加入 PATH，或设置 GODOT_BIN。
sdkmanager 'platform-tools' 'build-tools;36.0.0' 'platforms;android-36'
python tools/export_android.py --sdk /path/to/android-sdk --jdk /path/to/jdk
```

已设置 `ANDROID_HOME`（或 `ANDROID_SDK_ROOT`）与 `JAVA_HOME` 时可以省略参数。其他系统可在 Godot 编辑器内配置 SDK 并使用同名预设导出 Debug APK。

首次导出会把官方 Gradle 模板安装到 `build/android-project/`，下载 Gradle 与 Maven 依赖；模板版本不一致时重建这个生成目录。该目录不入库，开发者通过编辑器导出时也须安装 Android build template。采用 Gradle 是为了正确编译 Vulkan 的必需功能声明，避免 Godot 4.6.3 非 Gradle 导出生成错误属性类型。

产物在 `build/packages/wdfz-android-debug-arm64.apk`，旁边有 SHA256 和来源提交信息；日志在 `build/reports/android/`。脚本验证 APK 签名、Debug 标记、包名、SDK 版本、ARM64 架构、启动横屏、必需的 Vulkan 设备功能与 Mobile 元数据、ZIP 完整性、16 KB 原生库对齐、项目入口／声音索引／Android 纹理，确保开发目录未打包。CI 缓存开发签名以便后续覆盖安装；缓存或本地密钥丢失后签名会变化，需要先卸载同包名的旧调试包，卸载会清除该包的本机存档。

到 [Android Debug 的成功运行](https://github.com/wd-fz/wdfz/actions/workflows/android-debug.yml) 下载 `wdfz-android-debug-arm64-<SHA>`，完整解压后安装 APK。也可使用 `adb install -r build/packages/wdfz-android-debug-arm64.apk`。APK 及校验信息保留 7 天，日志保留 14 天。通过这些构建检查不等于真机启动、触屏、画面或性能验收。

需要把安装包长期保留在草稿 Release 时，先建立目标提交为完整 SHA 的草稿，再手动运行 [Android Draft Release](../.github/workflows/android-draft-release.yml)，填写草稿的 `release_id`、成功 Android Debug 构建的 `run_id` 和完整 `source_sha`。必须在上述 Artifact 过期前运行。流程下载原始 APK，核对来源、SHA256 与构建信息，再上传 APK、校验文件和构建记录，保留原调试签名。

该流程只在手动触发时运行，使用仓库自动提供的 `GITHUB_TOKEN`（`actions: read`、`contents: write`），无需另设密钥。它只向现有草稿附加文件，不创建或发布 Release；重试跳过内容一致的附件，遇到同名不同内容的附件会失败，不覆盖。完成后日志和运行摘要给出草稿链接。


## 公开 Android Release

[Android Public Release](../.github/workflows/android-release.yml) 仅在 main 手动触发，输入 tag 必须与正式预设版本一致；首版为 `v0.1.0`。调试包的独立 workflow 和草稿附件流程仍保留。

需要仓库或组织向本仓库提供 `ANDROID_KEYSTORE_BASE64`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD` 三个 Secret。密钥只在 runner 临时目录解码，权限为 0600，构建结束删除；密码通过环境变量交给签名器，不写进预设、命令参数或发布附件。密钥库密码与私钥密码使用这一个密码。签名材料不满足要求会失败，绝不回退为调试密钥。

流程先执行完整无窗口回归，再用固定 Godot release 模板导出、16 KB 对齐和签名，验证签名、不可调试、包名 `org.wdfz.godot`、版本、ARM64、启动横屏与 Vulkan 必需功能声明、Mobile 渲染器元数据和运行时资源。正式包默认不显示开发工具按钮。

发布 job 重新核对来源提交、干净工作树、APK／元数据／SHA256 一致性以及签名证书指纹；先上传到草稿并核对 GitHub 资产摘要，三项全部完成后才公开发布。已有公开版本不会被覆盖，失败后可对同提交的草稿重试。实际 Android 运行验收仍由真机测试承担，构建元数据中的 `runtime_verified` 保持 `false`。

正式 APK 与 `org.wdfz.godot.debug` 使用不同包名和数据目录，可以并存；用户不必卸载测试包，旧进度也不会自动迁入正式版。
