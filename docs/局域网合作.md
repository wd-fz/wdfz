# 局域网合作

在主菜单的「新的轮回」中选择「局域网合作 · 2–4 人」。由一台设备担任房主并运行世界模拟，其他设备连接它。无需云服务器或账号；没有公网匹配、中继和房主迁移。现有公开发行包不会因为源码更新而自动获得此功能。

## 建房与加入

1. 所有人使用相同构建。联机会核对协议、规则和内容指纹，混用不同代码版本会被拒绝。
2. 房主填写昵称、房间名、人数上限及难度，点击「创建房间」。默认游戏端口为 **UDP 24560**。
3. 房主在地址列表中选择实际连接路由器或热点的网卡，点击「复制选中地址」。不要把 `127.0.0.1` 发给另一台设备。
4. 其他人点击「查找附近房间」，或直接输入房主的 `IPv4:端口`，点击「加入」。发现使用 **UDP 24561**；发现失败不影响直接输入 IP。
5. 每人选择天赋并准备，房主开始。至少两人，最多四人。世界在成员完成加载后才开始计时；无法加载的成员可由房主移除，但开局仍需至少两人。

Windows 防火墙应允许本程序在当前可信网络上收发 UDP；Linux 防火墙应放行所用游戏端口，发现功能另外需要 24561。热点和访客 Wi-Fi 可能禁止设备互访；这时检查路由器的客户端隔离，或换普通局域网。虚拟组网若提供互通的 IPv4，可尝试直接输入地址，广播发现不保证跨虚拟网络可用。

Android 两个导出预设均声明 `INTERNET`，APK 验证脚本检查最终清单。Android 仍为横屏、强制全屏；桌面默认窗口化，Linux 原生 Wayland 的配置保留。手机进入后台可能被系统暂停或终止，因此房主应保持应用在前台。

## 合作规则

日历、检查、巡察者、门、电梯、设施冷却、容器、地面物品、路线和调查知识属于全队。SAN、违规、同化、体力、天赋、背包、手机电量、座位和生死属于每个成员。一天仍按现有约 20 分钟的自然日规则推进，逐日压力不会乘以人数。

- 每人有独立的本人座位，可分开探索不同楼层；客机只渲染自己的区域。队友身体不互相推挤，座位、柜子、电梯操作席和驾驶位仍检查占用。
- 「队伍」中选择背包物品，再点某位队友的「交付物品」。需同区域、两米内、无遮挡且对方能收下。物品按唯一实例转移，不会复制。两人争抢地面物品只结算一次。
- 最终死亡或正式离队时，物品留在原地点。地面容量已满时进入保护队列，有位置后重新落地；不会为了腾位置删除钥匙和材料。
- 巡察者全校只有一个。违规档位、永久追踪、躲藏和报点归属于本人；无线破解每 15 秒留下当时的静态位置。夜间普通归寝豁免不清除个人另行触发的责任。
- 个人背包、设置、手机、读书和暂停页只停止本人的操作，世界继续运行。房主可在队伍窗口发起最长 120 秒的全队暂停，任一在线成员可恢复。
- 会推进日历的休息、课堂等待和设施活动需要存活成员同意；支付、奖励和时间在确认后一起结算。取消、离开设施或遇险不会提前领取奖励。吃药等不跳时行为仍独立结算。
- 电梯只移动实际进入轿厢的人；队友站在门口会阻止关门。所有存活成员靠近车辆并确认后才开始驾驶；司机掉线时由在线乘客接手，没有可接手者则制动。
- 个人救助和预知梦沿用现有规则，不重置队友进度。最终死亡后可以跟随存活队友观战。房主死亡仍继续提供服务；没有新增队友无限复活。

## 六条公开结局

| 路线 | 合作方式与最后条件 |
| --- | --- |
| 白名单 | 网络中心、数据同步和闸机验证共用进度，可以分工；存活队友在闸机附近集合并确认。 |
| 闸门 | 一辆车、一名司机，其他成员确认乘车；共同完成追逐距离和分叉，最后确认结算。 |
| 门 | 图纸与建造进度共享，材料交给实际组装者；队友靠近已建成的门，各自确认进入后共同结算。 |
| 放学 | 通知稿、广播与长铃共用，操作者可和探索者分工；最后每名存活成员都要处在人群遮掩范围，不能由一人替远处队友通关。 |
| 网安仙人 | 终端席位互斥，已提交的服务器任务属于全队；倒计时不会随最初操作者死亡或退出终端而停止，存活成员确认结算。 |
| 外国语学生 | 共享语言验证、接待与行进路线；逐人计算掉队和搜索者威胁，所有参与逃离者需跟上队伍到终点。 |

一局只结算一个共同结局。暂时断线的存活成员在保留期内仍需返回确认；房主也可明确移除。最终确认会重新检查位置和生死，提前确认后走远不能远程通关。死亡成员保留自己的死亡结果，同时记录全队结局。

首版合作暂不开放隐藏结局、个人特殊空间、DLC、额外个人支线（纸飞机、窗内视线、体检等）、手机小游戏和相册；这些内容保留在单人模式。普通电梯、公开路线需要的传送门隧道、粉笔标记、主体异象及上述六条公开结局可用。合作入口和不支持的操作会说明限制。

## 存档、断线与退出

房主每 30 秒及关键操作后保存，也可手动点击「保存合作进度」。退出时再保存一次。合作文件位于 Godot `user://cooperative/`，与单人槽位、成就及速通记录分开：

| 文件 | 内容 |
| --- | --- |
| `room.json`、`room.json.bak` | 房主的整局存档及上一个完整备份；临时写入、校验后替换。 |
| `connection.json` | 本机最近地址、昵称和原成员重连凭据；不要发送此文件给别人。 |
| `results.json` | 本机最近至多 100 局合作结果，包括成员、个人生死、全队结局和调试标记。 |

原成员断线保留 60 秒，身体停止移动但不获得无敌。点击「重连上次房间」恢复同一个角色、背包与进度；昵称不是身份，改昵称不能接管别人的角色。开局后不允许新成员补位；超时或被房主移除后，原凭据也不能再占用该角色。

房主退出会中断整局服务，客机停止预测并显示重连／返回入口。房主重新建房时可选择「恢复合作存档」，原成员使用自己的重连凭据回到大厅，准备后加载。恢复会切换会话代次，旧连接、旧场景输入和旧请求不会重放。已结算的存档不能继续开始一局。

## 调试与维护

队伍窗口显示身份、RTT、抖动、输入序号、已确认帧、收发字节、校正误差；房主另外查看活动物理区域、巡察目标及未确认快照。房主的恢复状态和传送操作统一经过权威命令，并给整局加调试标记；客机伪造这些命令会被拒绝。单人调试面板的直接写状态入口不用于合作局。

入口、协议、自动测试和实际验证范围见[局域网联机验证](局域网联机验证.md)。三平台真实设备互通与自然四人完整游玩仍需要设备验收；软件渲染窗口或回环网络测试不能代替它们。
