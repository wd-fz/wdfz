# 局域网联机验证

对应[局域网联机计划](plan/局域网联机模式.md)，整体状态在[计划目录](plan/README.md)维护。本文记录实现边界和可复现的验证入口，不把受控测试夹具称为自然游玩。

## 实现落点

| 层 | 入口与责任 |
| --- | --- |
| 房间与日历 | `CooperativeRoom` 管理稳定成员、准备、加载屏障、暂停、保留期与共同结局；`SchoolCalendar` 每步只推进一次。 |
| 玩法 | `CooperativeActor` 持有个人模块；`CooperativeItems` 维护唯一物品、公共容器和保护队列；`CooperativePatrol` 调度唯一巡察实体与个人责任／证据。 |
| 装配 | `CooperativeFactory` 显式共享世界模块；`CooperativeContext` 构造个人上下文；`CooperativeGameplay` 适配交互、事件、路线和操作席位；`CooperativeSimulation` 驱动权威固定步。 |
| 连接 | `LanTransport` 使用独立 `SceneMultiplayer` 子树和 ENet；`LanSession` 处理握手、身份、重连、快照与生命周期。 |
| 协议 | `LanProtocol` 只收发有限大小的 JSON 数据，拒绝非有限数值和对象；`LanChunks` 限制重组大小、期限及校验散列；`LanDiscovery` 提供可选 UDP 发现。 |
| 存档 | `CooperativeValidation` 在装配前校验候选；`CooperativeStore` 管理独立合作槽位、备份、凭据和结果。 |
| 碰撞 | `CooperativePhysics` 为活动区域创建隔离的、不渲染模型的 `World3D`，复用校园碰撞数据；`CharacterMotor` 与单人共用速度和运动规则。 |
| 表现 | `LanFlow` 接入真实 GameApp 与设备输入；`LanPrediction` 保存有界输入历史并校正；`RemoteStudents` 插值远端人物；`LanPanel` 提供横屏触控房间界面。 |

共享模块：校园门、设施、路线、车库、广播、外国语队伍、调查笔记和粉笔标记。其余模块按成员实例化。成员记录保留首次／最近参与的模拟时刻、在线游玩时长和存活时长，离线保留及结算后的停留不计入；数据随合作检查点和独立结果保存。远端人物在同区域播放空间脚步声，跨楼层、躲藏及过期运动快照不会继续发声，也不产生巡察者威胁字幕。

持久化额外记录正在回答的题目、搜索、终端连接、广播朗读、车库作业、电梯乘员、个人生死和报点队列；共享内容恢复时不会重新发奖励。房主物理导航使用专属实例，避免被房主自己的表现会话覆盖门碰撞回调。

协议初版参数：模拟 **60 Hz**、输入 **30 Hz**、运动 **20 Hz**；完整规则快照 **5 Hz**，压缩分片后发送。运动与输入使用独立的有序不可靠通道；控制与基线各用可靠通道。每个客机一次只等待一个快照确认，重发需要匹配快照序号，持续不确认会断开。单片原始压缩数据 16 KiB，解压后基线至多 2 MiB，重组缓存至多一份、15 秒过期；输入超过 250 ms 未更新即归零。房间广播有递增版本，跨通道的旧加载状态不能覆盖进行中状态；未确认的基线重发保留原序号，延迟 ACK 不会被新的序号永久拒绝。ENet 允许 60 秒场景加载，应用层另用单调实时时钟检测握手、心跳与断线保留期。收到消息时直接读取当前时间，避免场景加载后把上一帧时间当作收包时间；本地首个 Vulkan 帧绘制完成后才解除加载屏障。关闭客户端间转发，只允许客机与房主通信。

每次修改协议相关运行时代码或校园 JSON 后执行 `python tools/lan_manifest.py` 并提交 `assets/lan_manifest.json`。构建不依赖导出包中存在 GDScript 原文；握手直接读取已生成的指纹。`tools/check.py` 检查指纹是否与源码一致，不能靠旧 manifest 绕过版本检查。

## 自动测试

先使用项目锁定的 Godot 版本导入：

```bash
godot --headless --path . --editor --import
python tools/check.py --static-only
python tools/test_lan.py --rules
python tools/test_lan.py --players 2
python tools/test_lan.py --players 2 --slow-load
python tools/test_lan.py --players 4 --faults
python tools/test_lan.py --players 2 --restore --faults
python tools/test_lan.py --players 2 --ending --faults
python tools/test_lan.py --players 2 --ui
python tools/test_lan.py --players 4 --faults --soak --seconds 1800
```

- `run_unit.gd`：日历跨日、独立座位／SAN、唯一拾取、压缩基线、无效输入、全队暂停和原成员身份。
- `authority.gd`：重复事务、实际发送者权限、过期代次／场景、隔墙拾取、物品保护队列、跳时同意、进行中存档及备份恢复、巡察责任隔离、物理空间、死亡与六条公开结局。
- 多进程：每个成员是独立 Godot 进程、独立用户数据目录和真实 ENet 连接。覆盖大厅加载、跨区域、全队暂停、断线重连、房主死亡后继续服务和观战数据。
- `--slow-load`：客机首次基线处理阻塞 12 秒，验证慢速场景构建仍能完成加载和后续重连。
- `--restore`：房主关闭后重新读取合作检查点并开房，客机用原凭据重新加入；验证会话代次更新、身份不变、唯一钥匙实例不复制、楼层位置及共享进度恢复。该用例也经过弱网代理。
- `--ending`：两进程从大厅进入，分别操作真实白名单终端，经历原成员断线重连，回答闸机问题并共同结算。为了固定测试时长，由夹具放置角色、提供 U 盘；不等同于从零收集和步行探索的自然整局。
- `--faults`：UDP 代理固定随机种子，单向延迟 40±10 ms、3% 丢包、1% 重复，调度延迟产生乱序。保留实际转发、丢包和重复计数。
- `--soak`：四个进程连续运行，轮换不同楼层／室外、反复创建和释放区域，同时记录模拟耗时、内存、节点与区域峰值。该夹具保护人物数值以避免死亡提前结束负载，明确属于稳定性测试。

有 Vulkan 显示环境时：

```bash
xvfb-run -a python tools/test_lan.py --players 2 --ui --renderer forward_plus
xvfb-run -a python tools/test_lan.py --players 2 --ui --renderer mobile
xvfb-run -a python tools/ci/with_wayland.py python tools/test_lan.py --players 2 --ui --renderer forward_plus --display-driver wayland
```

`--ui` 使用实际主场景、房间窗口、个人暂停与原地死亡演出，覆盖触屏面板边界、键盘 H 的权威命令路由、取消大厅后返回单人菜单及快照刷新时控件身份不变。为了在 CI 软件 Vulkan 上验证界面，独立测试设置使用「流畅」预设；不修改玩家的默认画质，也不把该测试作为硬件性能成绩。窗口用例必须取得真实 Vulkan 设备并核实显示后端，不能以无窗口通过代替图形通过。结果、每个进程的日志与故障统计输出到 `build/reports/lan/`；脚本错误即使引擎返回 0 也判失败。

`.github/workflows/lan.yml` 单独执行规则和 ENet 测试、X11 上 Forward+／Mobile 两种原生窗口，以及原生 Wayland 上的 Forward+ 双窗口。Wayland 测试使用 Weston 虚拟显示，游戏通过原生 Wayland 协议连接。30 分钟测试通过手动 workflow 的 `soak` 参数运行，普通提交不重复消耗半小时。原有 `godot.yml` 的结构、单人回归与导出检查继续保留。

## 本轮证据与边界

本地完整单人无窗口回归 **20,438 项、零失败**；合作规则 **119 项、零失败**；四进程弱网 **31 项通过**；双进程白名单弱网 **10 项通过**；房主重新开房恢复存档弱网 **20 项通过**；慢加载 **21 项通过**；实际 GameApp 的触屏／键鼠 UI 无窗口用例 **32 项通过**。规则用例包括共享天气调度者死亡后的连续性、个人伤害和事件不串人、延迟 ACK、过期房间状态、畸形操作参数和慢帧后的心跳时间。单人座位提示与奔跑操作另做 **20 项专项复测**。原始结果以 `build/reports/lan/` 为准。

首轮 30 分钟四进程弱网测试完成了负载，但出现一次 ENet 断连通道错误，因此未记为通过。已关闭不需要的客机转发并检查有效通道，修复后的长时间复测仍在进行。两种 Vulkan 原生窗口由分支 CI 验证，结果完成后更新本节。

本地执行环境没有 Vulkan 显示依赖且没有安装系统包的权限，因此双 Vulkan 窗口以 CI 实际运行结果为准，不能把本地 `--ui` 无窗口结果记为 GPU 验证。Android APK 权限的工具测试已覆盖缺少 `INTERNET` 的拒绝分支；本轮未发布安装包。

以下仍属于发布验收，不能由回环或软件渲染推定通过：Windows／Linux／Android 混合设备互通，Android 房主的触控软键盘、前台温度与性能、后台中断，Linux 原生 Wayland 的联机窗口，以及四人自然完整探索通关。需要登记具体设备、系统、网络、实际版本和帧耗时；没有真实设备证据时不宣称三平台联机已完成发行验收。
