## 1. 目标、证据和修复原则

- **P0**：可能卡住正常通关、其他玩家操作或重要状态机；先补失败的回归测试，确认后优先修复。**P1**：多人规则错误、跨人串状态、时序一致性。**P2**：单人玩法与显示／输入缺口。**P3**：需先确认产品规则的隐藏内容和 DLC 扩展。
- **A：可由源码直接证明的调用链或边界不一致**，仍需运行验证实际表现；**B：高风险，须编写复现测试确认**；**C：明确的首版功能限制或有待产品决定**，不得在报告中冒充意外 Bug。条目的优先级不是发生概率。
- 核心约束：房主唯一权威、个人状态按稳定成员 ID、共享状态按世界实体 ID／实例 ID、物理效果只在房主结算；本地画面和声音不反写权威状态；所有持续操作有开始、占用、完成、取消、死亡、离队、断线、读档的闭环。
- 维持一局一个共同真结局；隐藏路线按上方已确认范围接入前置链路，个人假结局返回队伍。**不能仅删除限制判断或把隐藏 ID 追加到 `ENDINGS`**。
- 每项验收必须至少包含**正常交互路径**、两个独立进程／四进程适用场景、弱网／恢复适用场景；受控夹具可先固定难以随机出现的条件，但最终仍需覆盖真实按钮和权威命令的完整路径。单人模式必须继续通过回归。

## 3. P0：先确保玩家能正常玩完一局（C01、C02、C03、C29）

### C01 — 车辆准备、全员确认与驾驶状态机拆分

- **源码**：`game/features/garage/garage_module.gd`（`_job_tick` → `_drive` → `start_chase`）、`game/app/cooperative_gameplay.gd`（`apply_event("drive")`、`_board_car`、`_confirm_board`、`_garage_tick`）。
- **现状**：车辆任务结束时单人模块已设置 `chase != null` 和 `car_used`，随后联机 `_board_car` 因 `garage.driving()` 直接返回。正常入口可能没有创建上车确认。失败时又会清空成员的 `vehicle/driver/passengers`，却未对照 `GarageModule` 的追车、检查点、免死与预知梦状态完整收尾。
- **修复**：以 `car_ready` 事件取代单人立即驾驶；房主校验车辆、队员在场且无冲突 → 创建带唯一 ID 的上车提议 → 全员确认 → **一次**调用 `start_chase`。失败、保护生还、死亡、重连、司机离队各有确定状态迁移和清理；不得留下 `chase` 非空但无操作者的僵尸任务。明确同队员是否共用失败与继续机会。
- **验收**：两人从车库现实交互逐次试车直到正确车辆、确认上车、操纵追逐、成功结局；取消确认／有人离开／掉线／房主离队／失败后恢复，`chase`、`car_used`、`vehicle`、`driver`、`passengers` 始终一致。现有 `tests/network/authority.gd::car()` 直接调用 `_board_car` 的用例保留，但**新增不绕过车门任务的端到端用例**。

### C02 — 操作席位与租约的统一生命周期

- **源码**：`game/app/cooperative_simulation.gd` 的 `lease/release`，`game/app/cooperative_gameplay.gd` 的 `think/desk/lesson/facility_item/car/marks/phone/terminal/choose`。
- **现状**：有些瞬时操作在取得 `facilities`、`investigation`、`garage`、`marks` 等全局租约后，不生成选择框也没有释放路径；另有操作取消、死亡、断线才释放。一个人的普通交互可能阻塞另一人的不同设施。
- **修复**：区分**无锁查询／即时原子事务／按实体独占的持续任务**。即时操作执行后 `finally` 式释放；持续占用记录 `{resource_id, owner_member_id, generation, operation_id, expires}`，按实体（终端、车辆、广播台、设施）而不是整类 `facilities` 锁。拒绝时向玩家给出原因；切换场景、取消、成功、失败、离队、读档统一释放或恢复。
- **验收**：A 读个人课桌、看逃生思路、看车牌、写粉笔，B 仍可操作其他课桌／设施；两人争用同一终端只允许一人；持续任务取消后立刻可接手；恢复存档不继承不合法过期租约。

### C03 — 正式离队清理统一化

- **源码**：`CooperativeSimulation.departed/release/tick`、`CooperativeGameplay.disconnected/cancel_actor_jobs/_lift_tick/_lift_result/_garage_tick`、`CooperativeRoom.elapsed/remove`。
- **现状**：`departed` 移除物理体却保留 `actors` 对象；部分玩法遍历全部角色仅检查 `fate().over()`，不判断正式离队。可能继续作为电梯门口人、乘客、设施操作者或司机；手动移除与断线的司机接管处理也走不同路径。
- **修复**：定义唯一 `is_participating(id)` 和 `active_members()`；断线保留期**保留**个人状态、清空输入并继续承担危险，正式离队后**一次**清空各共享操作席位、车辆成员、门口占用、选项、广播、搜索和交付，并回收物品，禁止再被共享模拟选中。司机接管／无人接管时安全制动，区分断线和最终离队的恢复策略。
- **验收**：四人：B 站电梯门口被房主移除，门可关且 B 不随行；司机被断线或移除，有人接手时状态一致、无人接手时安全停止；离队者不再被计算为活跃目标。重复离队事件无副作用。

### C29 — 补真实入口测试，阻止“内部函数通过但实际无法游玩”

- **源码／现有测试**：`tests/network/authority.gd`、`tests/network/run_unit.gd`、`tests/network/experience.gd`、`tools/test_lan.py`。
- **策略**：固定种子只用于可复现，不得预先直接调用 `_board_car`、`_offer_ending`、`_confirm_time` 或跳过玩家会经历的选项／动作而宣称整条路线可用。保留受控规则测试，另建由实际 `GameApp`、UI 输入、网络命令进入的**自然路径**集成测试，覆盖六条公开路线的关键入口与结尾、失败重试、两人／四人、断线后重连。
- **验收**：CI 报告分别显示 `rules`／`real-entry`／`network-faults`／`soak`，报告包含使用的提交、渲染器、平台、测试人数与跳过项。任一 P0 真实入口失败即不标记“联机完成”。

## 4. P1：状态、个人边界、权威一致性（C04—C16、C27、C28）

### C04 — 《外国语学生》掉队恢复／失败规则

- **源码**：`CooperativeGameplay._exchange_tick/_ending_participants`。
- **现状**：掉队超时置 `_escort_lost[id] = true`，重新跟上只清 `_escort_lag[id]`；结局要求全部存活成员合格，可能形成不可清的资格阻塞。
- **修复**：明确“可在宽限期后重新归队”还是“该次路线失败可重新发起”；实现明确的恢复／重试状态机，禁止永久失格却仍要求该成员全队确认。
- **验收**：A、B、C 中 B 掉队→赶上、掉队→超时、B 离队、A 自行到终点四种情况不出现无法完成且无失败提示的死局。

### C05 — 所有交互应答与提议使用唯一 ID 和上下文校验

- **源码**：`CooperativeGameplay._choice/choose/_offer_time/_confirm_time/_offer_ending/_confirm_ending/_confirm_board`、`LanFlow.choice/send`、`LanSession`。
- **现状**：`choice["id"]` 已生成，但回答只传 `index`；上车、等待和结局确认主要传 `accept`。过期、取消后延迟到达的旧答复，可能作用于同场景新问题。
- **修复**：请求携带 `choice_id` 或 `offer_id`、成员 ID（以实际连接认证为准）、会话 epoch、场景版本；服务器只处理当前同 ID 事件，拒绝旧代次并幂等处理重复答复。客户端退出旧弹窗时必须清空待提交 ID。
- **验收**：延迟／乱序／重复、一个问题取消后马上出现同类问题、两名玩家并行选择，旧回答不会影响新题或重开新提议。

### C06 — 恢复大厅进入 playing 的状态归一化

- **源码**：`LanSession.host(resume)/_control("loaded")/remove`、`CooperativeRoom.check_loaded/elapsed`、`CooperativeSimulation.restore`。
- **现状**：普通 `loaded` 进入 playing 时有死亡状态修正，但加载期间“手动移除未加载者”或“保留期到期”也可能切换阶段，未走相同修正流程；这是**待验证的旁路风险**，非声称普通恢复必然复活死人。
- **修复**：将从任何路径转入 `playing` 的处理统一为一个原子阶段：角色 `fate` 与成员表 `state` 双向校验、准备模拟、清理过期选择与操作、更新观战资格、发房间状态。
- **验收**：恢复存档中一名存活、一名已死亡、一名未加载；移除未加载者后，死亡成员仍为 dead，不被列入 `alive_ids`，不阻挡结局，也不丢失原始个人死亡记录。

### C07 — 消耗中的物品按唯一实例完成与撤销

- **源码**：`BodyModule.use_medkit/tick`、`CooperativeItems.transfer/drop/recover`、`CooperativeGameplay.command("give"/"drop")`。
- **现状**：急救包治疗开始后计时，最终先生效再发 `remove` 事件；没有持续核验物品仍属于操作者。可以尝试在治疗中交易／丢弃，让效果与实际消耗脱钩。
- **修复**：开始时锁定实例 UID 或占用个人道具槽；移出背包即取消任务；完成时同一权威事务中验证状态→消耗指定 UID→发放恢复效果。其他长时间消耗道具逐项审查。
- **验收**：治疗中转交、丢弃、死亡、掉线、背包被其他事件改变、存档重连，不能免费恢复或重复消耗。

### C08 — 手机设备状态归属的产品规则与实现统一

- **源码**：`PhoneModule.device/capture/restore`、`CooperativeItems.owners/transfer`、`CooperativeGameplay`。
- **现状**：手机可交易，但无线进度、电量、容器和终端状态在个人 `PhoneModule`；转移道具并未转移设备状态。这是确认的**数据归属不一致**，须先决定是“个人账号状态”还是“真实一部手机”。
- **决策建议**：电池、无线接入、容器属于手机 `uid`；个人的阅读记录、角色秘密归本人；服务器停机任务属于世界。实现可持久化的 `phones_by_uid`，处理交付、拾取、丢弃、死亡和梦醒；严禁交易时复制已经完成的终端状态。
- **验收**：A 已联网的手机交给 B，按确定规则显示同一电量和网络；交换／掉落／死亡后手机不复制，进度不倒退，合作恢复文件能够准确还原设备和负责人。

### C09 — 隧道个人返回位置从共享装置状态拆出

- **源码**：`FacilitiesModule._enter_tunnel/_leave_tunnel`、`CooperativeFactory.SHARED`。
- **现状**：共享 `portal["ret"]` 每个玩家进入时覆盖，先进入者可能使用后进入者的返回点。
- **修复**：共享模块仅保存装置和图纸；按稳定成员 ID 保存返程位置／场景／朝向，验证原场景合法性；离队／死亡后清理，重连恢复。
- **验收**：A、B 从不同入口朝向先后进隧道，逆序离开，各自回到自己的合法位置；恢复存档后仍成立。

### C10 — 临时补给箱接回真实设施交互

- **源码**：`InvestigationModule.supply_offer`、单人 `GameApp` 设施交互、联机 `CooperativeGameplay.apply_result/choose/_confirm_time`。
- **现状**：联机已有补给 `supply` 的时间提议和领取结算，但未在交互设施前调用单人 `supply_offer` 逻辑。
- **修复**：共享调查条件触发一次可归属补给提议；房主校验补给地点、背包容量、是否已领取、是否有硬币及全队等待条件。竞态下只成功一次，取消不扣硬币不消耗补给箱。
- **验收**：从看讲台移交单→发现补给地点→真实走近柜台／售货机→拆封或付费领取；两人同触发、取消、离开、重连不会重复奖励或阻塞其他设施。

### C11 — 联机座位、NPC、提示与占用检查统一

- **源码**：`CooperativeFactory.actor`、`SchoolModule.assign_own_seat`、`CampusModule.hint/interact_at`、`CooperativeGameplay.apply_result`、`ClassmatesModule.layout`、`GameApp._show_classmates`、`assets/campus/layout/teach1.json`。
- **现状**：地图只有 `teach1:48:11` 原生 `P`，额外座位 `49–51:11` 是 `d`；服务器特判自己的课桌可坐，而其他玩家专座可绕过 NPC 检查进入搜索；客户端仍可能提示“翻找”。
- **修复**：建立统一的 `seat_id → owner_id, occupant_id, npc_reserved` 查询，不依赖把所有格子永久改成 `P`；在提示、坐下、翻找、学生会检查、NPC 生成、断线恢复中重用同一服务。普通教学模型和单人地图不应被联机覆写。
- **验收**：四人开局均在自己的座位，名称／座位判断正确；B 不能翻找正被 C 坐着的专座；离座后的物品／NPC 规则一致；准星提示与实际 E 动作完全一致；单人唯一原始座位无回归。

### C12 — 手机充电恢复为“本人的原教室”条件

- **源码**：`CooperativeContext.base`、`GameApp._phone_context`、`SchoolModule.in_classroom_here`、`PhoneEnergy.rate`。
- **现状**：联机上下文把任意符合条件的教学楼教室当作充电地点，单人额外要求原教室。
- **修复**：从玩家归属座位解析原教室及教室范围；无论房主、客机都使用同一判定；科技党、无线破解、机房插电脑按既定电量公式处理。
- **验收**：teach1 原教室充电、其他楼层同类教室不充电；穿教室边界／门口、同时联网和科技党耗电情况有确定数值断言。

### C13 — 服务器规则和单人异象表现桥接

- **源码**：`GameApp._anomaly_step/_chalk_step/_phantom_step`、`LanFlow._present`、`CooperativeGameplay.apply_event/_anomaly_tick`。
- **现状**：联机主要调用 `anomaly_fx.update`；单人的粉笔预告、低 SAN 幻觉、痕迹同步、笑脸等路径未全部接入，`smile` 等纯表现事件也无对应的联机客户端桥接。
- **修复**：分为 `world_authoritative`（异象种类／参与者／伤害）、`player_local_presentation`（预告、个人幻觉、音画）、`replicated_visual_event`（有序编号、对象 ID、重放去重）。客户端不得自行重算伤害；预告、提示、字幕和设置开关与单人一致。
- **验收**：同一异象安排下，房主和客机看到各自应有的预警、痕迹、惊吓与声音；弱网重发不重复扣 SAN，不重复播不可重入动画；关闭闪烁等本地设置独立。

### C14 — 车库黑影改为真正的多人观测／掩护

- **源码**：`GarageModule.lit/tick`、`CooperativeGameplay._garage_tick`、`CooperativeContext.base`。
- **现状**：黑影在一帧内主要通过单个角色上下文获取手电、位置、方向、速度等，队友照灯未被合并为同一怪物的观察结果，范围影响也可能错误归属单个玩家。
- **修复**：一个共享怪物、一份运动时钟；分别确定目标、所有合法手电光束、对各成员的近距离压力／碰撞与提示；不能因为人数变多而将黑影位移或冷却乘以人数。
- **验收**：A 开车，B 用手电掩护可实际影响黑影；C 距离黑影较近时只 C 受到适用的个人效果；穿门遮挡、多人同时开关手电、单人保留原难度。

### C15 — 课堂六倍加速改为全队权威模拟，而非纯跳时

- **源码**：单人 `GameApp._study_fast_forward`、联机 `CooperativeGameplay._confirm_time/_advance_time`、`SchoolCalendar`。
- **现状**：单人“整理到下课”运行额外完整模拟步，联机直接跳日历；虽然 `SchoolModule.advance_game_time` 仍会跨检查时刻处理队列，但不会对手机、巡察移动、持续恢复与伤害等执行相同秒数的完整模拟。
- **修复**：将课堂整理定义为全队确认后的“受控倍速模拟”而非通用休息跳时；保留危险中断，限制耗时、可取消，保持固定步与场景加载安全。普通休息／设施的独立跳时规则另做对照，**不得不分类型一律改成倍速**。
- **验收**：有队友巡察／无线破解／手机充电的课堂等待，对比单人正确推进量，检查不重复结算；有人遇险时提前退出而非跳过危险。

### C16 — 连续校园地面物品的真正跨区域可达性

- **源码**：`CooperativeItems.pickup`、`CooperativePhysics.can_exchange/reachable`、`GameApp._ground_step`、`LanFlow._present`。
- **现状**：`pickup` 先要求 `entry["world"] == a.location()`；同一连续校园内的区域门两侧即使接近也可能被硬拒绝。视觉目标选择和提示也应一起复核。
- **修复**：把普通校园地面实体定位到公共全局坐标，按真实 3D 距离、障碍、门、视线判定；仅对独立梦境／迷宫等隔离物理空间保持严格不可跨空间拾取。修改存档时保留旧 `world` 兼容读取。
- **验收**：门两侧打开／关闭、楼梯门洞、连廊两侧、跨高度、远处和真正特殊空间；两人争抢仍一次成功。

### C27 — 关键道具掉落与设施来源标记的端到端一致性

- **源码**：`GameApp._drop_item`（单人会清掉造门材料 `coil/lens/vial` 来源标记）、`CooperativeItems.drop/recover`、`FacilitiesModule.flags/portal`。
- **风险**：联机只按实例进行掉落／回收，未沿用单人的来源标志处理；材料被使用、丢弃、遗失、离队后的重新获取规则可能与单人不一致。
- **修复**：把“材料是否已从设施取出、现在在哪个 UID／保管队列、能否重新生成”定义为显式唯一实体状态；**不可**简单每次丢弃就生成第二份。修改前锁定预期的关键材料恢复规则。
- **验收**：四人轮流持有、地面已满、死亡后回收、丢弃后返回来源、读档重连，既不无故卡路线也不复制材料。

### C28 — 共享模块持久化和联机表现的全面一致性检查

- **范围**：`CooperativeFactory.SHARED` 的校园、设施、路线、车库、广播、接待、调查笔记、粉笔；`CooperativeActor.RUNTIME_FIELDS`；`LanFlow._snapshot/_present`；`CooperativeValidation`。
- **核查**：逐个字段注明全队／角色／一次操作的所有者，排查 `shared._c` 被后一个玩家上下文覆盖、结局条件被旧操作者锁定、共享任务更换负责人后的进度、读档现场重复发放事件、客户端漏展示异常或设备状态。已有保护需标记为“已有测试支持”，不能重复报 Bug。
- **验收**：四人分处不同区域、先后交互同一设施、在事件触发与接收之间断线／恢复。共享剧情同步一次、个人损失仅本人、重连后无幽灵弹窗／声音／任务。

## 5. P2：本地表现、输入以及单人玩法一致性（C17—C23）

### C17 — 连续空间巡察模型可见性与可听性

- **源码**：`PatrolModule.figure_visible/look_point`、`LanFlow._present`。
- **现状**：模型绘制资格仍主要判 `pat.room == player.scene`，需要实际验证连续校园门内外是否出现不合理消失；音效、字幕只按本地可感知范围。
- **修复**：基于连续校园的变换、视距与真实遮挡决定模型显示，不向隔墙玩家透露应隐藏的信息；保留特殊空间隔离。
- **验收**：楼门两侧、楼梯井、连廊、电梯前、同层不同逻辑区域的双窗口视觉与音效对照。

### C18 — 联机手机界面随真实电量和危险自动关闭

- **源码**：`GameApp._phone_shell_step`、`LanFlow._present`。
- **现状**：联机服务器继续耗电，客户端只刷新 UI，没有完全接入单人的关机／遇险／检查中自动关闭流程。
- **修复**：从权威快照产生个人 UI 关闭条件，避免本地提前扣电或自行恢复行动；关闭手机后恢复输入状态并清理小游戏。
- **验收**：零电、恢复到开机阈值、检查、终端切换、死亡／观战及客户端丢包情况下不出现永久遮挡的手机界面。

### C19 — 空格按住翻越的联机输入补齐

- **源码**：`BodyModule.tick` 的 `space`、`CooperativeContext.base` 固定 `space=false`、`LanFlow._physics_process` 输入包。
- **现状**：联机未发送该输入，交互键发起翻越的备用路径保留。
- **修复**：传权威可验证的“持续翻越意图／按钮状态”，只在真实靠近栏杆且可移动时累积；服务器执行实际翻越，客户端只做 UI 预测与撤销。
- **验收**：键盘／触屏、按住／松手、失焦、断线、临界场景切换和障碍判定与单人一致。

### C20 — 柜内久待规则是否对合作开放

- **现状**：`LockerOverstay` 的 45／55／65 秒警告及退出机制明确写了 *Single player only*，联机会重置；这是**有意限制**。
- **产品建议**：统一个人计时；如果巡察正追该成员或临近危险，则暂停推出计时；房主负责强制退出和 SAN，客户端只呈现警告。若决定联机继续禁用，必须在玩法文档明确列出，不作为未修 Bug。
- **验收**：两人躲不同柜子互不影响；另一人被追逐不应改变本人的“危险豁免”；断线及恢复计时有定义。

### C21 — 手机纸飞机小游戏

- **现状**：`GameApp._phone_select` 联机阻止 `plane`；本地游戏可运行，但单人得分会恢复 SAN。
- **修复建议**：个人本地画面、操作和音效不传全局；房主签发限时小游戏会话和奖励上限／校验规则，不采信客户端任意自报分数。联机开启手机时世界持续运行，遇险与死亡自动退出。
- **验收**：两人各玩各的互不影响，奖励仅本人一次；背景任务、时间、手机电池按房主继续计算；可在 Android 触屏正常退出。

### C22 — 机房贪吃蛇小游戏

- **现状**：单人使用 `SnakeGame/SnakePanel`，联机电脑菜单仍有对应文案，但 `PhoneModule.computer_choose(0)` 只发 `rest_pc`，没有打开小游戏。
- **修复建议**：在不冻结全队的前提下打开本地贪吃蛇；入场条件由房主判定；得分奖励有唯一会话和次数／上限校验；普通机房休息时间与小游戏额外奖励分开处理。
- **验收**：合作电脑真实交互打开小游戏、其他队友仍可探索；退出／突然断线不会被重复授予 SAN；无活动资格时明确提示。

### C23 — 本机相机、相册和闪光效果

- **现状**：`GameApp._phone_select` 联机禁止 `camera/album`，`_shoot` 有联机早退；单人拍照包含本地截图以及可影响巡察者的闪光。
- **修复建议**：图片仅保存本机独立合作相册，不塞入 5 Hz 世界快照，不向队友默认共享；闪光可见／影响巡察必须由房主以场景、位置、朝向、冷却和权限验证；涉及成就或调查进度的照片事件同样权威化。
- **验收**：自己可以拍摄队友，队友不能直接查看本机照片；闪光只影响真实可观察目标，连拍／重连不能重复触发，手机界面与性能正常。

## 6. P3：隐藏路线／个人空间／DLC 的单独扩展阶段（C24—C26）

> 首版文档明确禁止隐藏结局、个人特殊空间、DLC、纸飞机／窗内视线／体检等额外支线；此阶段是**产品功能扩展**，不与修 P0/P1 混作“已有功能的回归”。需先确立结局参与者和个人离队语义。

### C24 — 隐藏结局设计与前置链路

- **范围**：《先辈》《管制刀具》《盗梦空间》等；单人 `RoutesModule.offer_item`、`KnifeFlow`、`InceptionFlow`。
- **方案**：逐条画“发现线索→触发→演出／个人损益→是否回归→是否请求共同结局”的事件状态机。区分“个人经历并回到队伍”与“不可逆共同结束”；必须让队友知道但不窥探不应透露的私密提示。《先辈》涉及的丢弃条件需在权威物品事务中触发，不能只放开结局白名单。
- **验收**：其他成员仍可以移动、不会被单人 `SceneTree.paused` 冻住；一局只结算一个约定的全队结局，个人隐藏经历独立存档。

### C25 — 特殊电梯迷宫、梦境和重生

- **范围**：`CooperativeGameplay.apply_result("maze_enter")` 当前明确拒绝；`MazeFlow/InceptionFlow` 带有个人场景、失败回退与部分整树暂停行为。
- **方案**：服务器为成员建立隔离的特殊空间实例与入口／出口／重生位置；旁人校园世界照常推进；明确巡察是否能进入、队友能否救援、个人梦醒应否回到开局座位、断线后在哪恢复。
- **验收**：一人在迷宫、另外三人在不同楼层游玩，所有角色可以保存／恢复；退出、死亡、全队暂停互不串扰。

### C26 — 规则怪谈 DLC 和其他单人支线

- **范围**：规则怪谈 DLC、纸飞机支线、窗内视线、体检、相应成就和特殊事件。
- **方案**：逐条列明“纯个人幻觉”“只改变本人 SAN／选择”“修改全队世界”的边界；共享规则必须显式协商后才能启用，不能由一人本地设置更改所有人的规则。DLC 版本与内容指纹兼容、重连、存档需单独验收。
- **验收**：不支持时入口明确灰掉并解释；决定开放后有 2–4 人规则测试，普通合作和单人 DLC 均不回归。

## 8. 验收清单与失败判定

### 自动验证（每个实施 PR 都需记录）

```bash
godot --headless --path . --editor --import
python tools/check.py --static-only
python tools/test_lan.py --rules
python tools/test_lan.py --players 2
python tools/test_lan.py --players 2 --slow-load
python tools/test_lan.py --players 4 --faults
python tools/test_lan.py --players 2 --restore --faults
python tools/test_lan.py --players 2 --ending --faults
python tools/test_lan.py --players 2 --ui
python tools/test_lan.py --players 4 --faults --soak --seconds 1800
```

上述是已有工具入口；新增的真实入口用例应纳入既有 `tools/test_lan.py` 及 CI，避免引入只有开发者本地才会运行的测试。完整单人无窗口回归、实际窗口 Vulkan Forward+／Mobile、导出 APK 也不能省略。

### 必须新增的真实场景（不以直接调用私有方法代替）

1. **四人开局**：四座位、座位提示、NPC 占用、坐／站／翻找、课桌停车单与学生会检查一致。
2. **分工通关**：四人分别拿钥匙／照退车库黑影／完成车辆交互／确认上车到终点；失败后还能按规则继续。
3. **完整六条公开路线**：《白名单》《闸门》《门》《放学》《网安仙人》《外国语学生》分别通过真实入口到确认；包括取消、掉队、成员离队与不同位置再集合。
4. **共享行为竞态**：同设施双操作、同容器搜索、两人交易中掉线、道具使用时转交／丢弃、成员断线与正式离队；每个 UID 一处存在、每个效果一次结算。
5. **恢复和延迟**：旧选择回答与新选择交错、加载期移除未就绪成员、恢复时有死亡成员、途中保存广播／终端／隧道返程点、恢复后无租约残留。
6. **连续校园**：教室与走廊、不同楼门、楼梯、连廊的跨区域队友、拾取、巡察实体与音效，在门开／关时都合理；特殊空间隔离。
7. **资源与日程**：科技党与普通天赋无线破解、手机充电、课堂整理、全队等待、其他玩家仍移动和遭遇异象；跳时不复制奖励。
8. **客户端专属体验**：本地相册／小游戏按发布范围验证，照片不能偷偷发送；各自画质与减少闪烁互不影响；手机关机、游戏暂停、触屏输入能恢复。
9. **稳定性**：四进程 30 分钟弱网负载、跨运营商远程通道、Android 真机混合平台、温升与内存峰值、重连后真正继续同一角色。

### 完成定义（DoD）

- P0、P1 无未解释的真实入口失败；每项问题有**复现测试 → 修复提交 → 回归测试**三段证据，未完成的产品限制必须明确记录，不可用“功能已接入”代替。
- 公开合作支持的功能，与单人的规则差异均有书面理由与可见提示；一局单一共同结局、个人生命与道具状态不串人，房主死亡也不停服务。
- 不破坏既有单人存档和单人路线；合作存档可以验证并兼容性迁移。Android 真机和自然长局未跑就必须继续写“待验”。
- 更新 `docs/局域网合作.md`、`docs/局域网联机验证.md` 与本计划任务状态；**只有证据齐全时**才在 `docs/plan/README.md` 更新整体完成状态。

## 9. 不作为缺陷的已具备能力与边界

此前静态检查已找到房主权威、个人 SAN／背包、稳定物品 UID、巡察单实体、客户端快照后 `_sync_world()` 刷新门与电梯、基础结局确认和读档验证逻辑，不能重复将这些整体称为“未实现”。但有基础保护不代表所有自然交互路径都已通过。

原审计中相机／小游戏／隐藏结局属于主动限制，本轮按 C21–C26 扩大范围并单独验证。局域网自动发现失败而直接 IP 可连、Android 后台可能被系统终止、跨 NAT 无保证，仍属于网络边界，并非本计划声称已解决的 Bug。
