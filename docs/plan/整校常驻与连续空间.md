# 整校常驻与连续空间

将普通校园置于同一个三维／物理世界。进出楼、楼梯和连廊不替换场景，不在门槛读取资源；建筑仍按区域组织文件。状态见[计划目录](README.md)。

靠近建筑时，楼层间的外墙和高于室内模型的屋顶持续可见。电梯井和楼梯井按实际占地切分外墙，井外的墙段保留原有碰撞。轿厢升走后，两侧与背面的固定井壁仍阻挡玩家，正面的通行由各层电梯门控制。[食堂近景修复对照](../../pictures/合作角色/校园与角色修复对照.webp)

## 实施范围

1. 明确室外、所有普通楼层、楼梯、连廊、地下车库和正常电梯的统一坐标。保留区域 ID 与局部坐标作为玩法、存档和网络协议的边界，通过显式变换连接实际空间。
2. 开局预备并常驻基础模型和碰撞；取消普通校园的邻区预览副本、整楼阻挡体、门外封口和无限高的楼层碰撞。特殊异空间独立进入。
3. 人物跨区保持世界位置、速度、视角和输入，只变更所属区域。正常电梯在学校中移动；区域事件、灯光、声音、道具和巡察显示使用相同坐标变换。
4. 建筑按可见距离／楼层关系激活绘制，停止远区表现更新，保留真实碰撞和玩法状态。统一控制环境与灯光预算，画质切换覆盖全部常驻区域。
5. 权威联机使用同一校园碰撞空间，跨区队友按统一坐标显示；旧存档无需重写位置。增加接缝、上下楼、跨区联机、读档、质量切换与生命周期回归，测量首载、常驻内存和跨门耗时。

## 验收

- 普通区域往返不新增世界／碰撞实例，不进行模型读取、门口排队或重建。
- 各楼入口、楼梯每层和连廊双向可走；地面与墙体没有漏碰撞，楼层互不阻挡；地下车库出入口不被室外地面封住。
- 人物、异象、声音和互动物件没有偏移；本次水杯修复、死亡现场和存档继续有效。
- 联机两人分处门内外能够互相看到，权威移动与本机预测使用一致坐标和几何。
- 暂停、读档、重新开局、返回菜单不会留下灯光、异象、物理体或后台构建。
- 记录自动测试与软件 Vulkan 的实际结果，Android 真机的内存、功耗与长局体验单独列明，不把桌面测试当作真机验收。

## 实现说明

- `CampusSpace` 统一 40 个普通区域的实际位置；原区域 ID 与局部姿态继续用于规则、存档和权威命令。`CampusResident` 持有真实模型和碰撞，`PlayerFrame` 承接玩家的区域变换。
- 清理室外整楼占位碰撞、楼梯加厚边界、地下入口地面、固定假轿厢和门口封堵。实验楼旁连廊向东修正 1 米，仍落在原 3 米门洞内；桥下装饰不能再用十米高碰撞体挡住二楼。
- 远处使用按真实楼层高度裁切的外观，近处使用常驻内景；不会把整栋外壳叠在开放的门口。只有当前区域运行局部表现，环境、太阳和灯光继续受原有预算控制。
- 正常电梯的模型、碰撞和乘客一起移动；楼层归属切换保持世界姿态。纸飞机、窗边视线、声音、死亡与结局镜头都明确区分区域坐标和学校坐标。
- 首载分批准备整校碰撞，再预载入场附近的模型。加载页显示实际完成数，绘制第一帧后显示本机就绪。联机加载持续处理消息，房间统一放行后收起加载页。四人运动包每人只带一份姿态，传输采样精度为毫米／0.0001 弧度，权威状态和存档不取整。
- 特殊电梯空间、梦境顶层和传送门隧道继续保留独立边界。
- HUD 小地图显示当前位置和朝向，室内使用已探索楼层，室外使用从校园模型烘焙的卫星底图。点击小地图或按 G 打开大图，可拖动、缩放、定位，或切换到已探索楼层。手册的「任务」页可标记当前调查地点。

## 验证记录

入口为 `tests/suites/continuous_campus.gd`，覆盖所有普通入口与楼梯层的胶囊检查、两条连廊的两端、真实电梯位移、模型／碰撞实例复用、持续触屏输入、画质设置、存档、特殊空间、加载取消、镜头及四人运动数据。原有步行上楼、实体电梯门、死亡和结局流程继续由完整回归执行。

| 范围 | 本地结果 |
| --- | --- |
| 静态结构与工具 | 220 个运行时脚本、73 个规则脚本、390 个唯一 UID；内容指纹与工具测试通过 |
| 完整无窗口回归 | **21,635 项检查，0 失败**；通过标准入口 `python tools/check.py --mode headless` 完整运行 |
| 最终空间与表现专项 | Vulkan Mobile 331 项、Forward+ 332 项，均 0 失败；Forward+ 包含最后补充的权威跨区动量断言 |
| 人物／死亡与应用集成无窗口补验 | 1,081 项，0 失败 |
| 联机规则 | 单元、权威、界面入口、传输及路由合计 216 项，0 失败 |
| 四进程弱网 | 31 项，0 失败；涵盖运动快照、丢包、跨区和原身份重连 |
| 双进程实际界面 | 无窗口 43 项，Vulkan Mobile 49 项，均 0 失败；原生界面入口另外 38 项通过 |

原生双窗口使用 `tests/network/peer.gd` 的同一套检查，复测时仅加进度日志与较长的外层截止时间，确认先前的失败来自测试总时限。日志保存在不提交的 `build/reports/continuous-campus/` 和 `build/reports/lan/`。完整入口为 `python tools/check.py`，两种渲染器可分别用 `--mode windowed --renderer mobile`／`forward_plus` 运行；本地 Vulkan 结果为专项，不代表完整窗口套件已全部重跑。

完整无窗口回归先前与渲染测试并行时，在末段集成检查触及 30 分钟上限，未报告断言失败。全量用例现在会多次准备整校，运行器预算已调整为 40 分钟；随后停止并行渲染负载，按上述标准入口完整跑通，保留全部原有检查。结果及摘要位于 `build/reports/headless/`。

2026-11-17 的 Linux llvmpipe／Vulkan Mobile 截图取样中，整校首次准备约 33.5 秒，Godot 静态内存分配约 505 MiB；七次区域选择耗时约 11–294 毫秒，模型与碰撞构建次数始终保持 40。这是区域切换函数耗时，包含当前区域表现激活，不是整帧耗时或帧率。内存数字也不等于进程 RSS 或全部显存。采样时其他回归仍在运行，数据用于暴露加载与内存成本，不作为独占机器或 Android 的性能基准。已检查教学楼内外、楼梯、地下车库、电梯、连廊及天台双向门洞画面。

两核测试环境同时运行完整回归和两个软件 Vulkan 窗口时，联机首载约需 80 秒，仍按区域更新进度并处理网络；原 216 秒测试总限时不足以容纳加载、模拟及重连后的观察区间。原生联机界面测试增加首载预算，保留所有断线／重连断言与总截止时间，无图形网络测试维持原限时。此处调整的是自动测试预算，不是游戏连接超时规则。

软件 Vulkan 与无窗口测试不覆盖 Android 真机内存峰值、热降频、持续功耗或多人自然长局。首载仍需要准备整校；普通通行阶段不再读取和重建基础校园几何。
