# 界面审美、控件布局与光影渲染

用户 2026-11-09 要求：优化界面审美；自定义触屏控件的布局；自定义键位；光影几乎看不出来，要体现；优化渲染。

本计划只改**表现与操作方式**：不改规则、数值、碰撞、地图与课表（CLAUDE.md「玩法与建筑都不能变」）。五档画质仍保持相同的玩法与碰撞；光影增强按画质档分级开启，低档不额外付费。旧版只作参考：旧版没有改键与逐个控件布局，这两项是 Godot 版新增的操作设置。

## 现状（main `d0e5d90`）

- 界面：`content/ui/theme.tres` 与 `ui_skin.gd` 已统一，主菜单／暂停双栏，卡片式设置。观感是通用的深色卡片，缺少本作的校园与恐怖气质；游戏内 HUD 是裸文字，物品栏只有「1·空 2·空」两行字。
- 触屏布局：`TouchLayoutEditor` 只能拖三组（摇杆、奔跑＋交互、工具栏），不能单独移动或缩放某个按钮，也没有透明度。
- 键位：写死在 `project.godot` 的 `[input]`，另有 R（课程）、N（笔记）、H（想一想）、M（静音）直接判断键码；没有改键界面。
- 光影：灯光照旧版 `lighting.js` 换算，环境是线性色调映射＋自己的 `ScenePost`；没有环境光遮蔽、没有辉光、房间灯与手电不投影，室内只有很弱的太阳光，白天黑夜、开灯关灯差别很小，物体之间没有明暗交界。
- 渲染：五档只调渲染比例、MSAA 与太阳阴影；比例小于 1 时是双线性放大，模糊。

## 约束

- Mobile 渲染器（Android）不支持 SSAO、SSIL、体积雾，开启受支持的灯光投影；FXAA 与辉光因发布时复现的死锁暂时关闭；每项都按 `RenderingServer` 的实际渲染器判断。
- 低档（流畅、均衡）保持现在的开销，新效果从「精细」起逐档加。
- 光影增强不改变「哪里看得见、哪里看不见」的玩法判断：巡察者视线、躲藏、异象判定都在规则层，不读画面。
- 彩蛋保密：本计划不涉及隐藏内容。

### v0.2.1 发布验证补充

Mobile 完整 CI 在「误读」档案回放超时；本地抓取线程栈后确认与 [Godot #123060](https://github.com/godotengine/godot/issues/123060) 的编译死锁相符。关闭 FXAA 后仍在蛾群回放停住，关闭 Mobile 辉光后已有缓存下全部回放恢复；三线程空缓存仍会卡住，固定八线程后空缓存全部档案回放通过。为固定版本引擎规避这些触发场景，Mobile 暂停这两项效果并固定工作线程池为 8，Forward+ 保留效果；Mobile 的低档放大改用引擎实际支持的双线性。详细策略见[渲染与 Vulkan 验证](../渲染与Vulkan验证.md)。原验收记录保留原提交范围，正式发布继续要求同一来源的三种完整回归与三平台构建通过。
