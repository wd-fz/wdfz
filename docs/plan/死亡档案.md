# 死亡档案（CG 档案馆）

以固定旧版 `death-archive.js`、规则怪谈 DLC 与 `run-record.js` 的实际运行结果为准。计划状态统一见[目录](README.md)，运行结果见[迁移一致性验证](../迁移一致性验证.md)。

## 档案规则

- 死亡按真实来源编号，不按共用特效合并：巡察者、车库、车门和驾驶是不同档案。救命药丸、天赋免疫、调试无敌先结算，真正死亡后才记档；预知梦惊醒前经历的死亡也计入。
- 调试面板打开、显式调试死亡与档案重播不记录；关闭面板后的自然死亡按照旧版当前事件上下文记录。这和成就、速通的整局可信标记是两种独立规则，不能混淆。
- 独立 `archive.json` 保存解锁、首次时间、经历次数、旧记录标记、直接解锁、已见过场和未知来源计数。旧 `death_log.json` 仅迁移一次；未知来源不猜测成其他死法。
- 公开死亡二十四份；隐藏三份只在取得后出现。演出包含开场、九条结局、电梯进出；隐藏项目不提前泄露。公开总数与已发现隐藏数分开显示。
- 开场和结局沿用原看过／达成标记；电梯进出播放完或跳过后记已见，取消不记。首次真实经历和调试直接解锁分开，直接解锁不制造死亡、结局、成就或评级记录。
- DLC 独立展示专属死亡与七项模式成就；九档结算画面使用真实最好一局，只有直接解锁而未取得时显示样例，不写入任何通关记录。

## 隔离重播

`ArchiveRules` 仅处理内容与记录；`ArchiveStore` 管理独立档案文件；`ArchiveFlow` 连接菜单与已完成的资料。`ArchiveStage` 创建自己的场景路由、玩家和音频，复用正式 `DeathCG`、`OpeningCut`、`EndingCut` 与 `MazeCut` 表现，不创建游戏会话。

电梯过场通过 `MazeCutStage` 接收表现依赖；正式游玩传入真实场景转移，档案重播仅切换自己的舞台。重播不能调用正式死亡、存档、成就或结局结算。

重播只从主菜单开始；返回、跳过、播放结束、新局、读档和退出清理专用模型、相机、声音及旧回调。退出回到原分类和条目；桌面与触屏均有返回入口。档案内容在屏幕内滚动，标题和分类保持在滚动区外。

## 验证要求

- 直接运行原 JavaScript 采集旧记录迁移、调试／重播／真实死亡组合、隐藏可见性和已见过场；采样同时记录旧运行时的开场与结局标记，不能假设均未解锁。
- 所有二十七种本体死亡、十二段演出和 DLC 死亡逐项搭建、推进、退出；比较正式玩家姿态、游戏音频随机序列、存档及递归资料目录的原始字节。
- 九档评级预览、真实最好成绩、直接解锁、菜单返回及新局取消分别验证。真实死亡须经过实际保命入口，不能仅手填档案验证。
- 原生窗口检查首次布局、横竖屏、字幕与返回按钮；截图脚本 `tools/capture/capture_archive.gd` 使用独立临时资料，并明确区分真实记录测试和直接解锁。

脚本与受控截图不能替代自然长局、Android 真机及实际听感验收。
