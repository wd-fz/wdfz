## 2026-11-11 修订：去掉标签、环绕默认关闭、功耗优化（用户指令）

用户反馈：进入主菜单要先点左侧标签；新界面功耗高、卡顿；环绕动画应默认关闭、可在后期打开。改动如下（上表是首版的事实，保留）：

| 项 | 状态 | 说明 |
| --- | --- | --- |
| 去掉左侧标签，直接进入 | 已完成 | 删除符文标签按钮与折叠状态：进入主菜单（开机动画结束、从游戏返回）时面板自动沿脊柱撕开并展开；展开过程中菜单项已可点击和聚焦，不再锁住菜单。点动作后只发出惨绿脉冲并褪回血痂色，面板不再坍缩 |
| 环绕默认关闭，可在设置打开 | 已完成 | 新设置 `menu_orbit`（「设置 → 画面 → 显示 → 主菜单实景环绕」，默认关）。关闭时不加载、不渲染任何 3D，菜单背后是静态夜景图；打开后才后台加载并环绕，关掉立即释放。打开时 3D 视图最多每秒重绘 20 次（`render_fps`） |
| 着色器功耗 | 已完成 | 去掉整屏截图读取（每帧复制并生成 mipmap 的屏幕纹理），面板改为对背景做透明度合成；所有程序化 FBM（每像素数十次哈希）改为一张预烘焙、可平铺的 256² FBM 贴图采样；毛玻璃改用菜单背景图的 48×27 预模糊副本；文字浮现着色器只在浮现时挂上，文字清晰后移除。开机动画着色器同样改用这张噪声贴图 |
| 静置降帧 | 已完成 | 正式启动的应用停在主菜单、1.5 秒无输入、无动画且没有打开任何面板时，帧率降到 30（玩家设得更低则按玩家设置），任何输入、动画或面板立即恢复。测试与工具内嵌的应用不受影响 |
| 后台加载竞态 | 已完成 | 之前 CI 窗口回归报 `Invalid Task ID`：菜单预览发起的后台加载与游戏同步加载同一个校园模型冲突。现在只有正式启动且打开了环绕时才加载，每个后台请求都会被收取一次（建好、离开菜单、任何场景准备加载模型前） |

性能对照（Xvfb＋Lavapipe 软件 Vulkan，1280×720，同一机器前后对比，只看相对变化）：主菜单展开静置每帧 48.5 ms → 25.0 ms（其中菜单着色器自身约 26 ms → 5.5 ms；没有菜单着色器时为 19.5–22 ms）；打开实景环绕时每帧 176 ms → 149 ms（再加 20 次／秒的重绘上限）。真机 GPU 上的绝对数值另需实测。

## 原菜单入口的归属

原主菜单的每个按钮都保留节点名与信号，只是收进五项之下：

| 菜单项 | 内容 |
| --- | --- |
| 继续入梦 | 读取存档（`LoadGame`），无存档时禁用 |
| 新的轮回 | 预知梦／梦魇新游戏（`NewGame`／`HardGame`）、速通、DLC 与模块、导入旧存档 |
| 画廊与遗物 | 成就、档案馆、通关记录 |
| 感官设置 | 设置、全屏、触屏操作、声音、开发工具（仅开发构建） |
| 逃离现实 | 退出游戏（走原有的正常关闭流程） |

校名按钮保持原样放在标题下方，原有行为不变。
