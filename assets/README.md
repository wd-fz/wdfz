# 资源导入约定

框架示例房间只用 Godot 基础几何体与系统字体。正式校园建筑在 [`campus/`](campus/README.md)，由 `tools/export_scenes/` 从旧版导出，不手工修改；`audio/` 中的音效由 `tools/audio_bake/` 按旧版配方烘焙。[应用图标](branding/README.md) 沿用旧 Android 壳的图案。其余正式资源按需建立子目录。

布局和声音索引 JSON 是运行时读取的非资源文件，当前所有导出预设通过 `assets/**/*.json` 显式包含它们。

[界面插画](ui/illustrations/README.md) 包含通过生图功能制作并实际接入的 41 件物品、7 个天赋、手机应用及背景。每个稳定 ID 有独立的 `AtlasTexture`，来源与图集重建方法在该目录记录。

- 统一 **1 Godot 单位 = 1 米，+Y 向上，-Z 为默认前方**。Blender 导出前应用缩放；不要在运行时叠加未记录的单位修正。
- 优先使用 glTF 2.0（`.glb`／`.gltf`）。保留可编辑源文件或生成脚本，不将 Three.js 专用 JSON 包当作通用模型格式。
- 旧版二维坐标到 Godot X/Z、旧高度到 Y 的变换应由迁移工具显式记录，并与旧 `U2M` 及朝向规则核对；不能只凭外观缩放。
- 网格、材质、碰撞和导航分别验收。LOD 或渲染质量变化不应改变玩法碰撞和房间可达性。
- 同一物件尽量共享材质和网格。确定导入后的尺寸、pivot、法线、贴图色彩空间、透明与阴影需求，再批量迁移。
- 每批外部资源附来源、版本、许可证、作者归属及加工记录。代码仓库的 AGPL 许可不能替代第三方资源本身的许可。
- 不提交 `.godot/imported/`；提交原始资源及需要保留的导入配置。避免在场景中硬编码本机绝对路径。

正式移动端包、纹理压缩档位、灯光烘焙、音频总线和字体打包留到对应移植阶段实测确定。
