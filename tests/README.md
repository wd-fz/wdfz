# 自动验证

`run_tests.gd` 只编排执行顺序、累计断言和退出码。原来的 101 个测试函数按功能迁到 10 个套件，77 个顶层用例保持原顺序，集成用例继续调用原来的行走、交互与路线验证。没有为目录调整删减断言；另外补充了结局演出取消后的生命周期回归。窗口路线测试通过真实 Space 输入跳过演出，再检查结局卡。

| 套件 | 范围 |
| --- | --- |
| framework | 时钟、模块协议、存档、应用生命周期、输入 |
| campus | 校园、门与电梯、背包、设施、探索 |
| school | 课表、检查、特殊日、怪谈、同学、伤势与感官规则 |
| story | 剧情、路线、天赋、调查与偶发事件 |
| threats | 巡察、异象、车库 |
| phone | 手机、终端、小游戏与广播 |
| atmosphere | 声音字幕、氛围与独白；固定并恢复氛围种子 |
| progress | 成就、速通、评分、记录与结果页 |
| presentation | 画面、UI、设置与导入适配器 |
| integration | 正式校园行走、上下楼、输入及各路线的组合回归 |

`support/test_suite.gd` 向当前 SceneTree 转发断言、帧等待与计时器，提供测试上下文辅助，不持有独立游戏局。新增测试须在 `run_tests.gd` 显式调用，避免文件存在但从未执行。

运行命令和 CI 解释见[项目结构与持续集成](../docs/项目结构与持续集成.md)。`tooling/` 使用 Python 标准库 unittest，验证架构检查与错误处理本身。不得把真实设备或完整自然游玩的结论从这些测试中推导出来。
